Mission briefing

Welcome to the Knowledge Base.

Today you are going to complete a small piece of real SOTE-style work. You do not need to know GitHub yet. This guide stays with you and tells you exactly what to do next.

TRAINING MISSIONACE-TRAIN-001

A classroom workstation problem has been resolved, but the solution is not yet documented. Your job is to learn how a technician turns that resolution into reusable knowledge.

Time: about 30–40 minutes

Format: instructor-led

Access: your own GitHub account

Training boundary

You do not need to join the SOTE organization or receive infrastructure access. Use only classroom-safe, fictionalized information.

Setup

Get GitHub ready.

We are going to use two browser tabs. Keep this training page open. The portal is your guide. GitHub is your workspace.

DO THIS

Open GitHub, sign in with your own account, then come back to this tab. Do not navigate anywhere else yet.

Open GitHub in a new tab ↗
Why two tabs?

You should never have to abandon the instructions to complete a task. Every time we send you to GitHub, return here for the next move.

Workspace

Meet the repository.

Now we will enter the CIT-205 classroom workspace directly. No hunting through GitHub menus.

DO THIS

Open the CIT-205 Classroom repository. Look at the repository name near the top of the GitHub page, then return here.

Open CIT-205 Classroom ↗
You just met a repository.

A repository is a project's workspace. It holds its files, folders, instructions, and change history. For this class, CIT-205 Classroom is our practice workspace.

Navigation

Find a knowledge article.

Instead of memorizing GitHub's interface, you are going to use it once and learn the pieces as you encounter them.

DO THIS

Open the knowledge folder below. Inside it, open the worked example. Notice the path GitHub shows above the file.

Open the Knowledge folder ↗
Repository → Folder → File

Knowledge

Inspect a finished article.

Before you create knowledge, see what useful technician-facing knowledge looks like.

DO THIS

Open the worked Knowledge Article. As a class, identify the problem, the checks performed, the resolution, and what another technician would need to repeat the fix.

Open worked example ↗
The point

A Knowledge Article is not a diary of what happened. It is reusable operational knowledge that helps the next technician solve the same problem safely and efficiently.

ACE-TRAIN-001

Turn the ticket into knowledge.

Now the mission becomes yours. You have a resolved support scenario. Your task is to convert it into a technician-facing article.

DO THIS

Open the training assignment. Read the scenario first. Then use the classroom Knowledge Article template to organize the resolution. Follow the instructor as we build the first sections together.

Open training scenario ↗Open KA template ↗
Workflow connection

The ticket records the incident. The Knowledge Article preserves what the organization learned from it.

Contribution

See how a change becomes accountable.

GitHub does more than store files. It records who proposed a change, what changed, and how that change was reviewed.

DO THIS

Open the example Pull Request. Look at the conversation and the changed file. Then open repository history and notice that each accepted change leaves a record.

Inspect example PR ↗View history ↗
Two words to keep

A pull request proposes a contribution for review. History shows the record of accepted changes. You do not need to master every GitHub feature to use this workflow.

Mission complete

You followed the Knowledge workflow.

You entered a repository, navigated to a file, inspected reusable knowledge, connected a resolved ticket to documentation, and saw how GitHub preserves review and history.

Ticket→Investigation→Knowledge→Review→Reusable Solution
What matters

GitHub is not the mission. The mission is contributing trustworthy knowledge to SOTE. GitHub is one of the tools underneath that workflow.
