CIT-205 Guided Mission

Improve an Existing Knowledge Article
Step 1 of 9
Mission briefing

Find knowledge. Improve knowledge.

This time you are not creating a new article. You are locating an existing classroom Knowledge Article, identifying a specific improvement, and proposing that change through GitHub.

TRAINING MISSIONACE-TRAIN-002

Improve the existing no-display Knowledge Article by making one troubleshooting decision point more explicit.

Locate

Start at the Knowledge Base index.

DO THIS

Open the classroom Knowledge Base. Under Worked Example, open EXAMPLE — Workstation Powers On but No Display.

Open classroom Knowledge Base ↗
Find before you change.

The index is the front door for accepted classroom knowledge.

Read

Read the official classroom copy first.

The page you opened is the official classroom repository on the main branch. This is the copy students read. Do not edit this copy directly.

WHAT YOU ARE LOOKING AT

At the top of GitHub, the branch selector should say main. The path should show CIT-205-classroom / knowledge / examples / KA-EXAMPLE-No-Display.md. That tells you that you are reading the current classroom version of this article.

TRAINING GAP

The article asks whether the monitor can display its own menu, but the troubleshooting steps never tell the technician what to do with that result.

PROPOSED CHANGE

Use the monitor controls to open its on-screen menu. If the menu does not appear, stop workstation-side troubleshooting and escalate the display or power issue. If the menu appears, continue.

Why open this article first?

You needed to inspect the accepted classroom version before deciding what should change. Reading happens here. Editing will happen in your personal fork.

Move to your workspace

Leave the classroom copy and open your fork.

You are currently looking at the shared classroom repository. Your edits belong in your personal fork, the copy you created in the first guided mission.

1 · OPEN YOUR GITHUB PROFILE

Tap your profile picture in the upper-right corner of GitHub. Open your repositories and choose CIT-205-classroom.

2 · CONFIRM YOU ARE IN YOUR FORK

On the front page of your copy, GitHub should show Forked from student-operated-technology-ecosystem/CIT-205-classroom. That line confirms you are in your personal fork instead of the official classroom repository.

Two copies, two jobs

Classroom repository: read the accepted version.
Your fork: build and propose the revision.

Prepare your fork

Start from the current classroom version.

You are on the right screen. Your fork's main branch is now up to date. The next move starts from the branch control you can see on this page.

1 · TAP THE BRANCH BUTTON

Find the button just above the file list that currently says main with a branch icon and a small down arrow. Tap main.

2 · OPEN THE BRANCH LIST

GitHub will open the branch chooser. If you see a search field, tap inside it. If GitHub shows a View all branches option first, open that.

3 · TYPE THE NEW BRANCH NAME

Enter revision/YOUR-GITHUB-USERNAME-no-display-menu.

Because that branch does not exist yet, GitHub should offer an option such as Create branch or Create branch from main. Choose that option.

4 · CONFIRM YOU SWITCHED

After GitHub creates the branch, return to the repository front page if needed. The same branch button that previously said main should now begin with revision/.

CHECKPOINT

Do not continue until the branch button shows your revision/... branch. If it still says main, open the branch chooser and select the revision branch you just created.

Why branch from main?

Your fork's main now matches the current classroom version. Creating the revision branch here gives your proposed edit a clean starting point and keeps main untouched.

Edit

Edit the existing file.

Now you will make one specific improvement to the existing article. You are not rewriting the whole document.

1 · OPEN THE ARTICLE IN YOUR REVISION BRANCH

Open knowledge/examples/KA-EXAMPLE-No-Display.md in your fork while your revision/... branch is selected.

2 · OPEN EDIT MODE

On mobile, use the file toolbar ••• menu and choose the edit option.

3 · FIND TROUBLESHOOTING STEPS

Scroll to the section headed ## Troubleshooting Steps. Find the first step:

1. Confirm that the monitor has power and observe its power indicator.

4 · INSERT THIS NEW STEP DIRECTLY AFTER IT

Paste this exact text as the new Step 2:

2. Use the monitor controls to open its on-screen menu. If the menu does not appear, stop workstation-side troubleshooting and escalate the display or power issue. If the menu appears, continue.

5 · RENUMBER THE REST

The old Step 2 becomes Step 3, the old Step 3 becomes Step 4, and so on. Do not change the wording of the other troubleshooting steps.

6 · PREVIEW THE ARTICLE

Use Preview and confirm the new decision step appears immediately after the monitor-power check and before the input/cable checks.

CHECKPOINT

Your article should now contain the new monitor-menu decision point and no unrelated edits.

7 · OPEN THE COMMIT WINDOW

Choose Commit changes…. Leave the confirmation window open and return to this guide for the next step.

Commit

Record the revision.

DO THIS

Use Add monitor-menu decision point to no-display article as the commit message. Commit directly to your revision/... branch.

CHECKPOINT

After the commit, the rendered article should contain the new decision step.

Propose

Open a pull request for the improvement.

DO THIS
  1. Return to the front of your fork.
  2. Open Contribute → Open pull request.
  3. Confirm your revision branch → classroom main.
  4. Confirm the diff modifies the existing no-display article rather than creating a second copy.
  5. Title it Improve no-display article — monitor menu decision point.
  6. Explain that the change turns an existing question into an actionable branch without claiming a specific hardware failure.
  7. Create the pull request.
Mission complete

You proposed an improvement to existing knowledge.

If the revision is reviewed and merged, the existing classroom article changes on main, while GitHub preserves the prior version in history.
