CIT-205 Guided Mission

Improve an Existing Knowledge Article
Step 1 of 9
Mission briefing

Find knowledge. Improve knowledge.

This time you are not creating a new article. You are locating an existing classroom Knowledge Article, identifying a specific improvement, and proposing that change through GitHub.

TRAINING MISSIONACE-TRAIN-002

Improve the existing no-display Knowledge Article by making one troubleshooting decision point more explicit.

Locate

Start at the Knowledge Base index.

DO THIS

Open the classroom Knowledge Base. Under Worked Example, open EXAMPLE — Workstation Powers On but No Display.

Open classroom Knowledge Base ↗
Find before you change.

The index is the front door for accepted classroom knowledge.

Read

Read the rendered article first.

Read it as a technician would use it. Then look for a place where the next action is unclear.

TRAINING GAP

The article asks whether the monitor can display its own menu, but the troubleshooting steps never tell the technician what to do with that result.

PROPOSED CHANGE

Use the monitor controls to open its on-screen menu. If the menu does not appear, stop workstation-side troubleshooting and escalate the display or power issue. If the menu appears, continue.

Prepare

Sync your fork before editing.

DO THIS
  1. Open your existing CIT-205-classroom fork.
  2. Switch to main.
  3. Use Sync fork if GitHub says your fork is behind.
  4. Confirm your fork main is current.
Why?

You want to revise the current article, not an older copy.

Branch

Create a revision branch.

DO THIS

Create revision/YOUR-GITHUB-USERNAME-no-display-menu from your updated fork main, then switch to it.

CHECKPOINT

The branch selector should begin with revision/. Do not edit while main is selected.

Edit

Edit the existing file.

DO THIS
  1. Open knowledge/examples/KA-EXAMPLE-No-Display.md in your fork.
  2. On mobile, use the file toolbar ••• menu and choose edit.
  3. Add the monitor-menu decision step after the monitor-power check.
  4. Renumber the remaining steps if needed.
  5. Use Preview to read the complete article.
  6. Choose Commit changes….
Commit

Record the revision.

DO THIS

Use Add monitor-menu decision point to no-display article as the commit message. Commit directly to your revision/... branch.

CHECKPOINT

After the commit, the rendered article should contain the new decision step.

Propose

Open a pull request for the improvement.

DO THIS
  1. Return to the front of your fork.
  2. Open Contribute → Open pull request.
  3. Confirm your revision branch → classroom main.
  4. Confirm the diff modifies the existing no-display article rather than creating a second copy.
  5. Title it Improve no-display article — monitor menu decision point.
  6. Explain that the change turns an existing question into an actionable branch without claiming a specific hardware failure.
  7. Create the pull request.
Mission complete

You proposed an improvement to existing knowledge.

If the revision is reviewed and merged, the existing classroom article changes on main, while GitHub preserves the prior version in history.
